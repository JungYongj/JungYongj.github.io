사내 표준 프레임워크가 없는 환경에서 WMS 입고·재고 모듈의 프로시저와 트랜잭션을 처음부터 설계했습니다.

어떻게 풀었나

입고 모듈을 처음부터

  1. 문제

    사내 표준 프레임워크가 없는 상태에서, SAP과 Non-SAP 환경을 모두 지원하는 신규 WMS를 만들어야 했습니다.

  2. 고민

    현장의 입고는 단순하지 않았습니다. 한 지시를 여러 BIN에 나눠 넣거나, 바코드 스캔과 수기 입력이 섞이는 경우가 많았고, SAP 수불 데이터와 WMS 실물 흐름이 어긋나지 않아야 했습니다.

  3. 해결
    • SAP I/F 수불 데이터로 입고 대상을 만들고, I/F가 없는 곳은 엑셀 업로드로도 등록할 수 있게 이중화했습니다.
    • PO 입고·창고 이동·반품 입고·기타 입고(선입고 포함)처럼 입고 유형마다 화면을 따로 두어, 유형별 절차가 섞이지 않게 했습니다.
    • 취소 문서가 내려오면 구매오더 번호와 취소 수량을 대조해 해당 줄을 빨간색으로 표시하고, 입고 수량에서 취소 수량만큼 빠지도록 했습니다.
    • 멀티 빈 팝업으로 한 지시 수량을 여러 BIN에 나눠 적치하고, 줄마다 스캔·수기 입력을 받습니다.
    • SKU 품목은 이력 추적을 위해 바코드 스캔으로만 입력받고, 보관 BIN은 바꿀 수 있게 했습니다.
    • [저장]은 임시 적치로 남기고, [완료]는 지시 수량과 적치 수량이 정확히 같을 때만 눌리며, 확정 뒤에는 수정할 수 없습니다.
    • 적치 이력에 BIN·분할 수량·작업자·SKU·부품인식표 번호를 남겨 재고를 추적할 수 있게 했습니다.
  4. 결과

    입고·재고 모듈 설계·개발을 전담하며 현업과 계속 협의해, 멀티 BIN 분할 적치와 스캔·수기 혼합 입력 같은 예외까지 견디는 입고 프로세스를 완성했습니다.

그 밖에 해낸 일

  1. PDA 스캔과 수기 입력을 모두 지원하고, 한 지시 수량을 여러 BIN에 나눠 적치하는 기능을 만들었습니다.
  2. 지시 수량과 적치 수량이 일치할 때만 확정되도록 해서 확정 이후 데이터 수정을 막았습니다.
  3. 상품화를 염두에 둔 WMS라, SAP 인터페이스가 없는 고객사에서도 쓸 수 있도록 엑셀 업로드로 입고 데이터를 등록하는 경로도 만들었습니다.
  4. 작업자가 금일 처리할 입고 대상과 잔여 수량을 한눈에 보도록 PO·품번 단위 조회 화면을 구성했습니다.
  5. 이 WMS는 Java Spring 기반 웹 시스템이고, 관리자 웹 화면과 PDA 웹앱을 함께 만들었습니다.
